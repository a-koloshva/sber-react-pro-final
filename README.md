## 2. Оптимизация рендеров

Найдены реальные проблемы с лишними рендерами и выполнена оптимизация.

### Что сделано

Использован **React DevTools Profiler** для поиска компонента, который рендерится чаще, чем необходимо. Это компонент Card.

Для этого применена подходящая оптимизация:

- `React.memo`;
- `useMemo`;
- `useCallback`.

В `React.memo` обернут компонент Card. Так как, карточек товара может быть много, а данные или состояния соседней карточки не меняются при обновлении выбранной.
При добавлении компонента в корзину, перерендеривался весь список компонентов, сейчас учитывается только переданный id товара и обновляется только та карточка, которая была добавлена в корзину.

`useCallback` использовался там, где необходима стабилизация функций, fetchMoreProducts  функция входит в зависимости  useLayoutEffect , который создаёт  IntersectionObserver . Стабильная ссылка помогает не пересоздавать observer при каждом рендере без изменения зависимостей.

`useMemo` используется для оптимизации вычислений. Список карточек товара, список корзины, список избранных товаров.

### Чек-лист

- [x] Использован React DevTools Profiler.
- [x] Найден хотя бы один hotspot.
- [x] `React.memo` используется там, где это действительно уменьшает количество рендеров.
- [x] `useMemo` применяется для вычислений, которые нет смысла выполнять при каждом рендере.
- [x] `useCallback` используется для стабилизации функций там, где это необходимо.
- [x] В README описано, что именно было оптимизировано.

## 3. React Portal для модальных окон

Реализовано универсальное модальное окно через **React Portal**.

### Требования к поведению

Модальное окно может:

- открываться и закрываться корректно;
- закрываться по нажатию `Escape`;
- корректно обрабатывать клик по overlay;
- управлять фокусом.

При открытии:

- фокус переходит на элемент внутри модального окна.

При закрытии:

- фокус возвращается на элемент, который открыл модальное окно.

### Чек-лист

- [x] Используется `ReactDOM.createPortal`.
- [x] Модальное окно рендерится внутри `#modal-root`.
- [x] Работает закрытие по `Escape`.
- [x] Корректно обработан клик по overlay.
- [x] При открытии фокус переходит внутрь модального окна.
- [x] После закрытия фокус возвращается на элемент-триггер.

## 4. Практическое применение useRef

Использован `useRef` в двух разных сценариях.

### Сценарий 1 — работа без перерендера

Использован `useRef` для хранения значения между рендерами без вызова нового рендера. Счетчик кликов.

### Сценарий 2 — работа с DOM

Использован `ref` для взаимодействия с DOM.

А именно:

- autofocus на поле логина;
- autofocus на поле регистрации;
- управление фокусом в модальном окне.

- [x] Есть пример взаимодействия с DOM через `ref`.
